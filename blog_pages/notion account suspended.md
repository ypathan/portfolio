However, some time ago, i had to access some previously created documents and was unable to do so and this motivated me to pick back up and project i had almost abandoned some time ago which was to convert my obsidian markdown files into html and then using a static file server to share them publicly.

Previosuly i had tried a few things, but they were based around the idea of replicating notion-like individual note sharing whereby i could specify a single file to be converted to html and be shared publicly, but that posed a problem because obsidian notes and not single files, especially when they contain images, images are files located in a separated directory and linked (not be the file system path), but u can specify in obsidian where the attachments will be stored and obsidian will itself by filename, find all images and attachments in the folder regardless of where the source file is located, meaning the relative path problem is not there anymore.

but this becomes a problem because when using tools like pandoc to convert markdown to html, because the relative path is not a thing, it cannot located the links plus i did not spend time on finding ways to specify to pandoc where linked files might be located. I also looked into some obsidian plugins that would expoert the entire vault as a directory to be shared, handing the image linking for you but that was not my goal at the time so i didnt go in-depth on this path, i also found tools (obsdian plugins) that would find the images and then embed them into the html as binary data but i could not find a way at the time to use the plugin api to call the plugin from external scripts so in the end i did come up with a hacky solution (i dont remember correctly now) where i could use some tools to export a particular note and then upload that manually to the server, and then use a golang file server to serve this, this is good for cases where i want to share notes with someone without letting them know and see the other notes there, cuz each note has a unique title so they cannot guess (hopefully) and it also had a private endpoint, through which admin can view all listed notes.

however, as of 2 days ago, thats not what i wanted. I wanted a public worklog which i would update on a daily basis, that included my daily logs along with appendix directory for other documents i created like guides etc... and so for this particular scenario, i first created a separate obsidian vault. and then i created a script that could be triggered to rsync my notes to my server. so in linux i used fuzzel dmenu to trigger the script and in macos i can use alfred workflow to trigger the script. on the server there a systemd service that a usinhg quartz to watch a particular directory and if it detects any change, it will auto run the quartz build command and generated html from the markdown, then i have a performance tuned nginx with heavy caching and other performance parameters configured, this will serve the files as i could not find a way to bind quartz --serve flag to 0.0.0.0 so i have nginx serving files on port 9000 and then another dokploy nginx container that will proxy the 9000 port traffic and bind it to the log.yousuf.life domain and give it the SSL certificate.
